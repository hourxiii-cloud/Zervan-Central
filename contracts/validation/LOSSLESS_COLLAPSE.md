R6-O implements native-v41 Lossless Collapse validation.

- object identity;
- capability;
- behavior;
- rationale;
- provenance;

- contracts;

## 1. Collapse Meaning

Lossless Collapse removes redundant implementation expression while preserving
independent semantic obligations.

Lossless Collapse != analytical Collapse Boundary.

Lossless Collapse != deletion by convenience.

Lossless Collapse != summary substitution.

Lossless Collapse != rewrite history.

---

## 2. Reconstruction Boundary

Native v41 is reconstructed from required invariants.

It is not required to preserve every historical file or duplicate expression.

It is required to preserve every independently necessary semantic obligation.

Historical quantity != required capability.

Old placement != required placement.

---

## 3. Independent Invariant

An independent invariant is a semantic obligation whose removal would alter:

- identity;
- behavior;
- capability;
- ownership;
- authority;
- admissibility;
- evidence treatment;
- lineage;
- provenance;
- replay;
- navigation;
- failure handling;
- auditability.

Independent invariant != duplicate wording.

---

## 4. Duplicate Residue

Duplicate residue MAY collapse when all semantic obligations remain represented
elsewhere with attributable lineage.

Duplicate residue MUST NOT survive merely because it existed historically.

Preservation != hoarding.

Historical presence != present necessity.

## 6. Object Identity

Collapse MUST NOT change canonical object identity semantics.

Implementation consolidation MUST NOT:

- mint replacement Room identity;
- merge distinct objects;
- convert representation identity into object identity;
- discard lineage required to reconstruct identity.

Identity preservation is mandatory.

---

## 7. Capability

A capability may move to another file, module, contract, or implementation
surface.

Placement may change.

Required capability may not disappear.

Replacement placement != capability loss.

---

## 8. Behavior

Observable required behavior MUST remain equivalent after collapse.

Equivalent implementation != identical source text.

Behavioral preservation includes rejection behavior.

Fail-closed behavior is behavior.

Negative behavior is behavior.

---

## 9. Rationale

Where an invariant depends on a non-obvious rationale, that rationale MUST remain
recoverable.

Rationale may be represented through:

- contract;
- audit record;
- provenance;
- validation receipt;
- explicit historical reference.

Rationale != every development conversation.

Rationale MUST NOT depend on private memory.

---

## 10. Provenance

Collapsed implementation MUST preserve provenance sufficient to explain:

- source obligation;
- retained implementation;
- removed duplicate;
- replacement relationship;
- validation basis.

Removal without lineage is not lossless.

---

## 11. Coordinates

Operational coordinates and return routes required by native contracts MUST
remain preserved.

Compression MUST NOT flatten navigable geometry into prose summary.

Coordinates != decorative metadata.

---

## 12. Transform History

Representation / transform history MUST remain reconstructible.

A compact implementation may replace duplicate transform records only when the
same material history remains attributable.

Collapse != history reset.

---

## 13. Contracts

Required contracts MUST remain represented.

Contract consolidation is permitted only when independent contract meaning is
not lost.

Similar contracts != same contract automatically.

No family absorbs another family merely for convenience.

---

## 14. Tests

Required behavior MUST remain testable.

Deleting duplicate tests may be valid where coverage remains equivalent.

Deleting the only test of an independent invariant is invalid.

Green count != coverage equivalence.

---

## 15. Evidence Boundaries

Evidence-boundary semantics MUST survive collapse.

A shorter implementation MUST NOT:

- broaden access;
- erase exclusions;
- convert restricted to absent;
- collapse bounded unknown into known;
- silently elevate evidence ceiling.

Compression != evidence expansion.

---

## 16. Known Failure Conditions

Known failure conditions are part of the system.

A lossless reconstruction preserves the ability to detect or reject known bad
states.

Failure knowledge != expendable residue.

A defect that can no longer be recognized has been lost.

## 17. Semantic Equivalence

A collapse candidate is lossless only if the retained implementation preserves
all independent obligations represented by the pre-collapse surface.

Textual equality is unnecessary.

Semantic accounting is mandatory.

Shorter != better unless invariant preservation holds.
